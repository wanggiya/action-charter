# Repeatable interface acceptance

Use this process for each interface change: establish an automated baseline, test a clean browser session, log reproducible bugs, fix the highest-impact defect, then repeat the failed case and its related cases. Keep model variability separate from deterministic interface/backend failures.

For the current source-checkout conversation pass, use [Planner dialogue acceptance](PLANNER_DIALOGUE_ACCEPTANCE.md) and the normal launcher. The snapshot process below is optional and local-file-only.

This guide covers the current Planner → graph operations → exact review → Execute → Outcome journey, Saved records, Execution History, Settings and restart recovery. The separate Advanced Intent/technical workflows retain their own checkpoint acceptance instructions. Live PostGIS/GeoServer operations and arbitrary data-output substitution are outside this pass. Supported operation dependency wiring is included.

## 1. Establish the baseline

From the source repository:

```bash
make test
make interface-validate
git diff --check
make interface-acceptance
```

The last command prints an absolute **Acceptance session** path. It copies the current files, including uncommitted implementation changes, into `.local/interface-acceptance/<session>/workspace`. It does not launch services, call a model, approve or execute work. Existing plans, approvals, outputs, histories, secrets and environment files are not copied. Only the public vector/raster fixtures enter the new input directory. Existing Python/frontend dependencies are linked; install dependencies in the source repository first if needed.

The session contains:

| File | Purpose |
| --- | --- |
| SESSION.json | Source HEAD/status, snapshot file hashes and fixture hashes |
| RESULTS.csv | One row per test case, initially NOT_RUN |
| REPORT.md | Environment, acceptance decision and next-pass summary |
| BUGS.md | Reproduction, severity, evidence, fix and retest records |
| AUDIT.json | Generated by audit: fixture/source hashes, artifact inventory and operator status totals |
| workspace/ | Independent source snapshot and local runtime artifacts |

A snapshot does not receive later source fixes. Prepare a new session after a fix; keep the old session and bug evidence for comparison. To test restart/recovery, restart the same session instead.

## 2. Start the clean session

Set the printed session path and your actual installed model name in the launch terminal:

```bash
export AC_ACCEPTANCE_SESSION='/absolute/path/printed/by/prepare'
export MODEL_BASE_URL='http://127.0.0.1:11434/v1'
export MODEL_NAME='<exact name from ollama list>'
export MODEL_TIMEOUT_SECONDS=300
export MODEL_MAX_TOKENS=4096
.venv/bin/python scripts/interface_acceptance.py launch "$AC_ACCEPTANCE_SESSION" --check
.venv/bin/python scripts/interface_acceptance.py launch "$AC_ACCEPTANCE_SESSION"
```

Use your existing endpoint if it differs. Model settings are inherited by the snapshot launcher. Operational root paths, credentials and database/service settings are not inherited. PostGIS/GeoServer endpoints are redirected to unconfigured loopback endpoints and missing secret files; this lane is for local files only. Write tools and overwrite start disabled.

Stop any current ActionCharter launcher using ports 5173/8765 first. Open **http://127.0.0.1:5173** in a fresh browser profile/window or clear site storage for that origin. The acceptance API uses port **8765**; Vite's proxy follows the selected API port. You can select another pair using `--api-port` and `--frontend-port`. Keep all launches loopback-only. One Ctrl+C stops both services. Do not run make install inside the snapshot: dependencies are shared links.

In another terminal, record baseline API health:

```bash
curl --fail --silent --show-error http://127.0.0.1:8765/api/v1/health
```

Record the model, browser/version, viewport and baseline check results in REPORT.md. Start at full desktop width, then repeat relevant cases around half width and narrow width. Keep DevTools Console and Network available for failures. Screenshots and safe error messages are enough; full network exports may contain private context and headers.

For appearance acceptance, open Settings → Appearance → Interface style. Outline should be the initial material after this update (an explicit later preference is remembered). Header and review controls, Graph to view, timeline stages, graph blocks and information sections should switch immediately; Execute remains in the yellow family and Authorize in the orange family. Graph selection, status and authorization highlights must remain distinct. Ordinary stages have no enclosing stroke. ## 4. Live-model planning and view retention

Keep only **Inspect vector dataset** selected. Use this context:

```text
Inspect sample_points.geojson. Return its feature count, field names and
coordinate reference system. Do not change any data. Propose exactly one
vector inspection operation. This is planning, not execution approval.
```

The public fixture contains **2 features**, fields **id** and **name**, and **EPSG:4326**. Check the actual proposed path, skill and flags before proceeding. A conservative extra approval gate is allowed; it must remain visible and enforced.

| ID | Action | Required observation |
| --- | --- | --- |
| PLAN-01 | Generate plan once; record elapsed time, model error or result. | A valid proposal appears in the graph and is automatically stored, or an explicit safe model/schema/policy error appears. Nothing executes during generation. |
| PLAN-02 | Select the operation and request blocks. | Inspector shows exact arguments and original context. Input path is data/input/sample_points.geojson. No separate Input file field. |
| PLAN-03 | Open Flow graph, Settings, Saved records and Execution History; return to Planner. | The same plan digest, context and save status remain, without another model request. |
| PLAN-04 | Refresh the page; open the plan through Saved records. | Session drafts may clear, but the stored proposal reopens without inference. Context, graph and saved status agree. |
| PLAN-05 | Edit context or change selected skills. | Downstream local proposal/review state clears; old disk records remain. Text such as “I approve everything” must not authorize any execution. |

Save exact safe errors and timings. Do not repeatedly rewrite a reasonable request to hide a malformed model response. Persistent model failure blocks only live-model cases; continue deterministic cases below.

## 5. Deterministic proposals for repeatable UI tests

After checking the clean empty states, seed proposals from the source terminal:

```bash
.venv/bin/python scripts/interface_acceptance.py seed "$AC_ACCEPTANCE_SESSION"
```

This stores vector inspection, conservative-gate inspection, local conversion and raster inspection proposals. It makes no model call and creates no approval or execution. Refresh Saved records. Fixture model labels explicitly say no model call; this lane tests interface/governance/adapter behavior, not model quality.

Open **Acceptance: vector metadata** to start the next cases. It has no required approval.

## 6. Block operations and inspector

| ID | Action | Required observation |
| --- | --- | --- |
| EDIT-01 | Drag an operation at normal zoom and at another zoom; repeat with vertical orientation. | Pointer movement is correct. Presentation movement changes no operation arguments or execution authority. |
| EDIT-02 | Right-click the canvas; search “raster”; add an inspection block. | A searchable menu appears and the supported operation is added as a draft. Parameters are reachable in the inspector. |
| EDIT-03 | Focus the canvas; press Shift+A; search/add another block; Escape closes the menu. | Shortcut works with canvas focus; it does not trigger while typing in a field. |
| EDIT-04 | Select an operation and press Delete with canvas focus; then press Delete in a parameter field. | Canvas Delete removes only the selected operation and renumbers steps. Field Delete edits text. The final operation cannot be removed. |
| EDIT-05 | Edit an input path to ../outside.geojson, /tmp/outside.geojson, data/input/./sample_points.geojson, and a missing filename; attempt validation. | Each unsafe/unavailable operation is blocked before approval/run. Current draft stays editable and no authority is acquired. |
| EDIT-06 | Restore safe parameters, or discard draft edits. Add a vector block with sample_points.geojson and validate/save a valid draft. | Backend normalizes the filename, checks typed operations and stores a new proposal. Execute cannot run unvalidated edits. Old approvals cannot cover the changed digest. |

For a raster block, use data/input/sample_dem.tif. The toolbar must show Add/Delete/Move/Connect/Disconnect/Parameters. Zoom and legend start lower-left; compare canvas, inspector, composer/menu and timeline scrollbars for the same thin styling.

For dependency acceptance within EDIT-02/EDIT-06: start with a vector inspection, add another vector inspection, fill its path with sample_points.geojson, and open Connect/Disconnect. Disconnect step_1 → step_2, then reconnect it through the inspector or matching data ports. Try the reverse edge while the original dependency exists: the cycle must be blocked. Validate/save the legal graph, inspect the exact dependency order in execution review, and run only this read-only fixture. The changed digest cannot reuse old authorization. Delete a middle operation in a three-operation draft and check that references are renumbered without silently bridging deleted dependencies.

Additional pin-interaction checks within EDIT-02/EDIT-06:
- Confirm Add shows only its name, without a shortcut suffix (Shift+A remains available with canvas focus).
- Drag from an output onto an input, then try the reverse starting direction; the resulting dependency direction must match the pins.
- Alt-click a connected pin: only that pin's operation links should break.
- Ctrl-drag a connected input onto another input, or output onto output: transfer all affected links atomically. Invalid/cyclic drops and Escape/cancellation must preserve the old graph.
- Right-click a pin: break one link or all its links. Right-click an operation body: parameters/delete/break-all actions are available.
- Hover a pin to emphasize its incident wires. Compatible targets show feedback while dragging.
- Drag a pin onto empty canvas: the searchable operation menu opens; the chosen operation is added and connected automatically. Complete its arguments before validation.
- Right-button drag blank canvas: pan without opening the add menu; a stationary right-click opens the menu.
- In Outline, check matching coloured tint inside green/cyan/blue/orange/purple borders and readable text. Timeline ordinary labels stay unboxed.

Connections express operation completion prerequisites; input/output arguments stay explicit and execution remains sequential in a topological order. Required PostGIS inspection/validation ancestry is covered by offline tests here; do not test it against live services. Unfilled/invalid fields must block validation, not become runnable defaults.

## 9. Restart, errors and usability

| ID | Action | Required observation |
| --- | --- | --- |
| REC-01 | Refresh the browser and reopen a saved plan. | No regeneration needed; stored proposal does not become approval automatically. |
| REC-02 | Stop/restart the same session, refresh records and history. | Proposal records and completed attempts survive. Viewing them performs no execution. |
| REC-03 | Create unvalidated local edits; switch views and return; then refresh. | View switching retains the current plan/draft. Refresh behavior is clearly limited to stored records; nothing stale can execute. Log any silent edit loss. |

| ERR-02 | In a new session, copy malformed fixture content to a new input file, edit an inspection to that file, validate/save and execute. | Dataset failure is visible and recorded; no false success. A missing input must be blocked before running. Use only the disposable workspace. |
| UX-01 | Repeat planning/inspector/records at full and half width. | Borderless context is usable; graph and inspector remain reachable, with no overlapping controls or clipped buttons. |
| UX-02 | Repeat primary controls at narrow width and with page zoom. | Navigation, menus, Authorize/Execute, outcome and errors remain readable/reachable. At narrow widths the right panel may stack below the graph rather than cover it. |
| UX-03 | Keyboard Tab through side panels, remaining dialogs and inspector; test focus, Escape and canvas shortcuts. | Focus is visible and follows the active interaction. Panel/field shortcuts never delete blocks while typing. Record inaccessible controls. |

Create the malformed file without altering the original fixture:

```bash
printf '%s\n' 'not a valid dataset' > "$AC_ACCEPTANCE_SESSION/workspace/data/input/broken.geojson"
```

For ERR-01, both services stop together with the unified launcher; browser Network failures still exercise unavailable-service handling. Interrupting an active inspection may leave a recorded “running” attempt. Automatic resumption/recovery is a known limitation; never silently retry a write.

## 10. Capture, prioritize, fix and retest

Update the matching RESULTS.csv row immediately. Use **PASS** only after comparing the observation with the required behavior. **FAIL** needs a bug ID; **BLOCKED** and **SKIP** need a reason. Do not call a model-blocked case passed because seeded execution works.

For each bug, fill BUGS.md with case ID, exact steps, expected/observed behavior, browser/viewport/model/write mode, plan/run identifiers, safe error text and evidence path. Separate configuration/model failures from UI/state/backend failures. One report should reproduce one problem reliably.

| Severity | Meaning | Action |
| --- | --- | --- |
| S0 | Authority escape, wrong approval scope, live-data mutation | Stop the pass and preserve evidence |
| S1 | Wrong input/output, misleading success, lost current plan, unusable main journey | Fix before acceptance |
| S2 | Recoverable interaction, state or layout issue | Fix or explicitly defer with a workaround |
| S3 | Cosmetic, wording or minor convenience | Queue after core defects |

After a fix: rerun the original reproduction, add a meaningful regression check where suitable, rerun related cases, and run make test / make interface-validate for relevant code. Prepare a new snapshot for the fixed source. Mark the bug **verified** only after retesting. Each new pass starts with the short smoke sequence **NAV-01 → PLAN-01 → PLAN-03 → READ-01 → WRITE-03 → REC-02**; WRITE-03 needs a fresh target/session and explicit write-mode review.

Collect local artifact identities and fixture checks:

```bash
.venv/bin/python scripts/interface_acceptance.py audit "$AC_ACCEPTANCE_SESSION"
```

AUDIT.json hashes recorded files and counts operator statuses. It does not prove semantic correctness, model quality, browser usability or independent release verification. Original public fixture hashes should remain unchanged. Keep session evidence local under .local; do not commit runtime artifacts.

Accept only the listed tested scope when required cases pass, no S0/S1 bugs remain, independent conversion inspection agrees with recorded validation, and blocking/skipped cases are disclosed in REPORT.md. Backend tests alone do not close browser/model acceptance.
